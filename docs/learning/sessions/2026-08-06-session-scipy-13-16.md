### Explanation

Facts verified against Python 3.13.11 / numpy 2.4.1 / scipy 1.16.3 / sklearn (env): (1) scipy.stats.multipletests and tt_ind_solve_power are NOT public in 1.16.3 — implement Bonferroni/BH and normal-approx power formulas manually. (2) np.unique(return_counts=True) returns (values, counts) — unpacking wrong order feeds chisquare silently. (3) sp.eliminate_zeros() is in-place, returns None — chaining .nnz raises AttributeError. (4) sp.random's data_rvs receives size POSITIONALLY in 1.16 — rng.uniform fails with ValueError('high - low < 0'); use data_rvs=lambda k: rng.uniform(lo, hi, size=k). (5) Sparse sum(axis=1) returns a 2-D matrix-like — np.asarray(...).ravel() before sp.diags. (6) Max-Sharpe with equal uncorrelated vols is the tangency portfolio w ∝ Σ⁻¹(μ−rf), NOT all-in on the best asset ([0.727, 0.273] for excess [0.08, 0.03]) — my initial test expectation was mathematically wrong. (7) robust least_squares: with +40 outliers, linear slope 6.66, soft_l1/huber stall in a bad basin ~7.19, cauchy recovers 2.02 — the lecture's key lesson, asserted deterministically in tests. (8) Cosine on unit vectors: euclid² = 2·cosine_distance exactly; normalize-then-euclidean ≡ cosine ranking. (9) Curse of dimensionality: pairwise cosine spread ≈ 1/sqrt(d) (0.707 at d=2, 0.088 at d=128); cKDTree 4× faster than brute at d=2 but 4× slower at d=64 on 20k points — timing verified. (10) scipy metric name for Manhattan is 'cityblock'. (11) L1 row normalization ≠ unit L2 — scaled rows have unit L1, not L2 (my first example 8 bug). (12) Memory guards: tracemalloc peak for spsolve(2000 tridiagonal) = 0.024 MB vs 32 MB dense; sparse retrieval 0.08 MB vs 80 MB dense; cKDTree 50k×1000 queries < 10 MB vs cdist ~400 MB.
