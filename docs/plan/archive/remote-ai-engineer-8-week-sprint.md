# Remote AI Engineer 8-Week Sprint

This sprint is tailored for a full-stack AI engineer in Egypt targeting remote AI/LLM roles. It turns the roadmap into concrete delivery milestones using Athar as the main showcase project and Baligh as the second proof of depth.

## Sprint goals

- Convert existing AI work into production-ready portfolio evidence.
- Show strong Python, FastAPI, RAG, evaluation, deployment, and documentation skills.
- Produce artifacts that match remote hiring signals for AI/LLM engineer roles.

## Weekly plan

| Week | Objective | Repo deliverable | Hiring signal |
|---|---|---|---|
| 1 | Audit the current codebase and clean the Python/FastAPI foundation. | `docs/architecture-overview.md`, refactor branch, type hints, config cleanup, tests. | Signals code quality, maintainability, and production discipline. |
| 2 | Define API contracts and response schemas for core AI workflows. | `docs/api-contracts.md`, Pydantic request/response models, example payloads. | Signals structured engineering and reliable backend design. |
| 3 | Run retrieval experiments on Athar with at least 3 chunking/retrieval strategies. | `docs/retrieval-experiments.md`, benchmark table, sample queries. | Signals real RAG engineering and evidence-based iteration. |
| 4 | Build an evaluation harness for RAG quality and error analysis. | `docs/rag-evaluation.md`, metric report, failure taxonomy. | Signals ability to measure quality, not just build demos. |
| 5 | Add agent/tool orchestration for one useful workflow. | `docs/agent-workflow.md`, prototype agent, tool list, prompts. | Signals agentic design and tool-use competence. |
| 6 | Package and deploy the project as a public demo. | Dockerfile, deployment notes, public URL, `/health` endpoint. | Signals deployability and end-to-end ownership. |
| 7 | Turn Baligh into a second showcase artifact focused on training/eval/release structure. | `docs/baligh-showcase.md`, training pipeline summary, model card draft. | Signals breadth beyond RAG and stronger LLM depth. |
| 8 | Polish portfolio and prepare remote applications. | `docs/case-studies.md`, CV bullets, LinkedIn summary, GitHub README refresh. | Signals readiness to apply and communicate value clearly. |

## Delivery standards

Every week should end with at least one visible artifact: a doc, benchmark, demo, or code branch. If a week produces only notes, it is not done. The goal is to create a repo that a recruiter can inspect in under five minutes and immediately see production-level thinking.

## Portfolio framing

Athar should be presented as the main production RAG system: Arabic-first, retrieval-heavy, evaluation-driven, and deployment-ready. Baligh should be framed as the model training and fine-tuning companion project that shows you can work across the full AI stack.

## Risk controls

- Keep scope tight; do not start a third major project.
- Prefer measurable progress over feature count.
- Write documentation while implementing, not after.
- Commit daily and keep branch history understandable.

## Done criteria

You are ready to start applying when you have:

- One public demo or deployable endpoint.
- One evaluation document with metrics and failure analysis.
- One agent/tool prototype.
- One second project that proves model-side depth.
- A portfolio README that explains both projects in English.
