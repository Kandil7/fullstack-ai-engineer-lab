## Detailed Definitions

### Vector

**Definition:** An ordered array of numbers representing data in a high-dimensional space. Vectors capture relationships between data points through their positions and distances.

**Example:**
```python
import numpy as np

# Simple 3D vector
vector = np.array([0.23, -0.15, 0.89])

# Higher-dimensional (typical for embeddings)
embedding_vector = np.array([
    0.023, -0.156, 0.089, 0.234, -0.067,
    # ... 1536 total dimensions
])

print(f"Dimensions: {len(embedding_vector)}")
print(f"First 5 values: {embedding_vector[:5]}")
```

**Related Terms:** Embedding, Dimension, Similarity

**Key Properties:**
- Fixed dimensionality per model
- Dense (most values non-zero)
- Learned from data
- Enable mathematical operations

---

### Embedding

**Definition:** A dense vector representation of data (text, image, audio) that captures semantic meaning. Similar items have similar embeddings.

**Example:**
```python
from openai import OpenAI

client = OpenAI()

# Generate embedding
response = client.embeddings.create(
    model="text-embedding-3-small",
    input="The cat sat on the mat"
)

embedding = response.data[0].embedding
print(f"Vector dimensions: {len(embedding)}")  # 1536
print(f"First 5 values: {embedding[:5]}")

# Similar texts have similar embeddings
response2 = client.embeddings.create(
    model="text-embedding-3-small",
    input="A feline rested on the rug"
)
embedding2 = response2.data[0].embedding

# These should be close in vector space
```

**Related Terms:** Vector, Semantic, Similarity, Model

**Key Points:**
- Generated by embedding models
- Capture semantic relationships
- Enable similarity search
- Fixed dimensions per model

---

### Similarity

**Definition:** A measure of how alike two vectors are. Higher similarity means vectors are closer in the embedding space.

**Example:**
```python
import numpy as np

def cosine_similarity(a, b):
    """Measure angle between vectors (-1 to 1)."""
    return np.dot(a, b) / (np.linalg.norm(a) * np.linalg.norm(b))

# Example vectors
vector_a = np.array([1, 0, 0])
vector_b = np.array([0.7, 0.7, 0])
vector_c = np.array([-1, 0, 0])

print(cosine_similarity(vector_a, vector_b))  # ~0.71 (similar)
print(cosine_similarity(vector_a, vector_c))  # -1.0 (opposite)
```

**Related Terms:** Cosine, Dot Product, Euclidean, Distance

**When to Use Which:**
- **Cosine:** Most common, normalized, robust to magnitude
- **Dot Product:** Fast when vectors are normalized
- **Euclidean:** When absolute distance matters

---

### Dimension

**Definition:** The number of components in a vector. Higher dimensions can capture more nuance but require more storage and computation.

**Example:**
```python
# Different models produce different dimensions
models = {
    "all-MiniLM-L6-v2": 384,      # Small, fast
    "text-embedding-3-small": 1536, # Balanced
    "text-embedding-3-large": 3072, # High quality
}

model_name = "text-embedding-3-small"
dimensions = models[model_name]

# Create vector with correct dimensions
vector = [0.0] * dimensions
print(f"{model_name}: {dimensions} dimensions")
```

**Related Terms:** Vector, Embedding, Model

**Trade-offs:**
- Lower: Faster, less storage, lower quality
- Higher: Slower, more storage, higher quality
- Common: 384, 768, 1024, 1536, 3072

### Chunk

**Definition:** A segment of text split from a larger document for embedding. Chunks balance context preservation with embedding quality.

**Example:**
```python
def chunk_text(text, chunk_size=500, overlap=50):
    """Split text into overlapping chunks."""
    words = text.split()
    chunks = []
    
    for i in range(0, len(words), chunk_size - overlap):
        chunk = " ".join(words[i:i + chunk_size])
        chunks.append(chunk)
    
    return chunks

# Usage
long_document = "..." * 10000  # Long text
chunks = chunk_text(long_document, chunk_size=500)
print(f"Split into {len(chunks)} chunks")
```

**Related Terms:** Overlap, Context Window, Embedding

**Strategies:**
- Fixed-size: Simple, consistent
- Sentence-based: Preserves grammar
- Semantic: Splits at meaning boundaries
- Recursive: Hierarchical splitting

### Vector Database

**Definition:** A specialized database designed to store, index, and query high-dimensional vectors efficiently. Optimized for similarity search.

**Example:**
```python
import chromadb

# Create vector database
client = chromadb.Client()
collection = client.create_collection("documents")

# Add vectors
collection.add(
    documents=["Doc 1", "Doc 2", "Doc 3"],
    ids=["doc1", "doc2", "doc3"]
)

# Query by similarity
results = collection.query(
    query_texts=["similar document"],
    n_results=2
)

print(results["documents"])
```

**Related Terms:** Index, HNSW, Similarity Search

**Popular Options:**
- ChromaDB: Local, simple
- Pinecone: Managed, scalable
- Weaviate: Self-hosted, hybrid
- Milvus: High performance
- Qdrant: Filtering focus

### Semantic

**Definition:** Relating to meaning in language. Semantic search understands the meaning behind queries, not just keywords.

**Example:**
```python
# Keyword search fails
# Query: "happy" won't match "joyful"

# Semantic search succeeds
from sentence_transformers import SentenceTransformer

model = SentenceTransformer('all-MiniLM-L6-v2')

docs = ["I am happy today", "She feels joyful"]
query = "happiness"

doc_embeddings = model.encode(docs)
query_embedding = model.encode(query)

# "happy" and "happiness" will have high similarity
```

**Related Terms:** Embedding, Similarity, Meaning

**Key Advantage:**
- Understands synonyms
- Grasps context
- Handles paraphrases
- Cross-lingual potential

### Normalization

**Definition:** Scaling a vector to have unit length (magnitude of 1). Required for cosine similarity to work correctly.

**Example:**
```python
import numpy as np

def normalize(vector):
    """Normalize vector to unit length."""
    norm = np.linalg.norm(vector)
    return vector / norm if norm > 0 else vector

# Before normalization
vector = np.array([3.0, 4.0])
print(f"Magnitude: {np.linalg.norm(vector)}")  # 5.0

# After normalization
normalized = normalize(vector)
print(f"Magnitude: {np.linalg.norm(normalized)}")  # 1.0
print(f"Values: {normalized}")  # [0.6, 0.8]
```

**Related Terms:** Magnitude, Cosine, Vector

**Why It Matters:**
- Cosine similarity assumes normalized vectors
- Prevents bias from vector magnitude
- Enables fair comparison
- Most embedding APIs return normalized vectors

### Index

**Definition:** A data structure that enables fast similarity search in vector databases. Common types: HNSW, IVF, Flat.

**Example:**
```python
# HNSW index (Hierarchical Navigable Small World)
# - Fast approximate search
# - Good for large datasets
# - Trade-off: memory usage

# IVF index (Inverted File Index)
# - Clusters vectors
# - Fast for very large datasets
# - Trade-off: requires training

# Flat index
# - Exact search
# - Small datasets only
# - Trade-off: slow at scale
```

**Related Terms:** HNSW, IVF, Vector Database

**Considerations:**
- Build time vs query time
- Memory usage
- Accuracy (approximate vs exact)
- Dataset size

### Embedding Model

**Definition:** A neural network trained to convert data into dense vector representations. Different models have different dimensions, quality, and speed.

**Example:**
```python
# OpenAI model
from openai import OpenAI
client = OpenAI()

response = client.embeddings.create(
    model="text-embedding-3-small",
```

**Selection Factors:**
- Dimension count
- Quality benchmarks
- Cost per token

### Tokenizer

**Definition:** The algorithm that splits text into tokens before embedding. Different models use different tokenizers, affecting embedding quality.

**Example:**
```python
import tiktoken

# OpenAI tokenizer
encoding = tiktoken.encoding_for_model("gpt-4")

text = "Hello, world!"
tokens = encoding.encode(text)
print(f"Tokens: {tokens}")
print(f"Token count: {len(tokens)}")
print(f"Decoded: {[encoding.decode([t]) for t in tokens]}")

# Different tokenizers may split differently
# "don't" -> ["don", "'t"] or ["do", "n't"]
```

**Related Terms:** Token, Encoding, Preprocessing

**Key Points:**
- Different models = different tokenizers
- Affects max document length
- Influences embedding quality
- Important for chunking

### Cosine Similarity

**Definition:** A metric measuring the cosine of the angle between two vectors. Returns values from -1 (opposite) to 1 (identical), with 0 meaning orthogonal.

**Example:**
```python
import numpy as np

def cosine_similarity(a, b):
    """Calculate cosine similarity between vectors."""
    a = np.array(a)
    b = np.array(b)
    return np.dot(a, b) / (np.linalg.norm(a) * np.linalg.norm(b))

# Identical vectors
print(cosine_similarity([1, 0, 0], [1, 0, 0]))  # 1.0

# Similar vectors
print(cosine_similarity([1, 0, 0], [0.9, 0.1, 0]))  # ~0.99

# Orthogonal (unrelated)
print(cosine_similarity([1, 0, 0], [0, 1, 0]))  # 0.0

# Opposite
print(cosine_similarity([1, 0, 0], [-1, 0, 0]))  # -1.0
```

**Related Terms:** Dot Product, Euclidean, Similarity

**Why Popular:**
- Magnitude-invariant
- Bounded range [-1, 1]
- Intuitive interpretation
- Fast computation

### HNSW

**Definition:** Hierarchical Navigable Small World - an approximate nearest neighbor algorithm used in vector databases for fast similarity search.

**Example:**
```python
import chromadb

# HNSW is default in ChromaDB
collection = client.create_collection(
    "documents",
    metadata={
        "hnsw:space": "cosine",  # Similarity metric
        "hnsw:M": 16,            # Connections per node
        "hnsw:ef_construction": 200  # Build quality
    }
)

# Higher M = better quality, more memory
# Higher ef_construction = better index, slower build
```

**Related Terms:** Index, ANN, Approximate Search

**Characteristics:**
- Fast query time (logarithmic)
- Good recall accuracy
- Memory intensive
- No training required

### Dot Product

**Definition:** The sum of element-wise multiplication of two vectors. Similar to cosine similarity but not normalized.

**Example:**
```python
import numpy as np

a = np.array([1, 2, 3])
b = np.array([4, 5, 6])

# Dot product
dot = np.dot(a, b)
print(f"Dot product: {dot}")  # 32

# For normalized vectors, dot product = cosine similarity
a_norm = a / np.linalg.norm(a)
b_norm = b / np.linalg.norm(b)
print(f"Normalized dot: {np.dot(a_norm, b_norm):.3f}")  # ~0.97
```

**Related Terms:** Cosine, Similarity, Vector

**When to Use:**
- Vectors are already normalized
- Need maximum speed
- Absolute values matter

### Dimensionality Reduction

**Definition:** Techniques to reduce the number of dimensions in vectors while preserving important information. Used for visualization and compression.

**Example:**
```python
from sklearn.manifold import TSNE
import numpy as np

# High-dimensional embeddings (1536D)
embeddings = np.random.rand(100, 1536)

# Reduce to 2D for visualization
tsne = TSNE(n_components=2, random_state=42)
reduced = tsne.fit_transform(embeddings)

print(f"Original: {embeddings.shape}")  # (100, 1536)
print(f"Reduced: {reduced.shape}")      # (100, 2)
```

**Related Terms:** t-SNE, PCA, Visualization

**Common Methods:**
- t-SNE: Non-linear, good for visualization
- PCA: Linear, fast
- UMAP: Fast, preserves structure

### Clustering

**Definition:** Grouping similar vectors together without predefined labels. Useful for organizing embeddings into topics or categories.

**Example:**
```python
from sklearn.cluster import KMeans
import numpy as np

# Sample embeddings
embeddings = np.random.rand(100, 1536)

# Cluster into 5 groups
kmeans = KMeans(n_clusters=5, random_state=42)
clusters = kmeans.fit_predict(embeddings)

print(f"Cluster assignments: {clusters[:10]}")

```

**Related Terms:** K-Means, Topics, Categories

**Use Cases:**
- Topic discovery
- Document organization
- Duplicate detection
- Content recommendations

### Upsert

**Definition:** A database operation that inserts new records or updates existing ones if they already exist. Common in vector databases.

**Example:**
```python
import chromadb

collection = client.create_collection("docs")

# Upsert - insert if new, update if exists
collection.upsert(
    ids=["doc1", "doc2"],
    documents=["Updated content 1", "New content 2"],
    metadatas=[
        {"version": 2},
        {"version": 1}
    ]
)

# Second upsert updates doc1
collection.upsert(
    ids=["doc1"],
    documents=["Version 3 of content"],
    metadatas=[{"version": 3}]
)
```

**Related Terms:** Insert, Update, Vector Database

**Why Important:**
- Keep embeddings current
- Avoid duplicates
- Efficient updates
- Maintain consistency

### Batch Processing

**Definition:** Processing multiple embeddings simultaneously for efficiency. Reduces API calls and latency.

**Example:**
```python
from openai import OpenAI

client = OpenAI()

# ❌ Slow: Individual calls
texts = ["text1", "text2", "text3", "text4", "text5"]
for text in texts:
    response = client.embeddings.create(
        model="text-embedding-3-small",
        input=text
    )

# ✅ Fast: Batch call
response = client.embeddings.create(
    model="text-embedding-3-small",
    input=texts  # All at once
)
embeddings = [item.embedding for item in response.data]
```

**Related Terms:** Latency, Efficiency, API

**Benefits:**
- Reduced API calls
- Lower latency
- Better throughput
- Cost efficiency

### Overlap

**Definition:** The number of shared tokens between consecutive chunks. Maintains context across chunk boundaries.

**Example:**
```python
def chunk_with_overlap(text, chunk_size=100, overlap=20):
    """Create overlapping chunks."""
    words = text.split()
    chunks = []
    
    for i in range(0, len(words), chunk_size - overlap):
        chunk = " ".join(words[i:i + chunk_size])
        chunks.append(chunk)
    
    return chunks

# Example
text = "word " * 150
chunks = chunk_with_overlap(text, chunk_size=100, overlap=20)

# Each chunk shares 20 words with the next
print(f"Chunk 1 ends: {chunks[0].split()[-5:]}")
print(f"Chunk 2 starts: {chunks[1].split()[:5]}")
# Should show overlap
```

**Related Terms:** Chunk, Context, Continuity

**Why Important:**
- Prevents information loss at boundaries
- Maintains context
- Improves retrieval quality
- Typical: 10-20% of chunk size

### Recall

**Definition:** The proportion of relevant documents found by a search. Higher recall means fewer missed relevant results.

**Example:**
```python
def calculate_recall(retrieved_ids, relevant_ids):
    """Calculate recall@k."""
    retrieved_set = set(retrieved_ids)
    relevant_set = set(relevant_ids)
    
    if not relevant_set:
        return 0.0
    
    found = len(retrieved_set.intersection(relevant_set))
    return found / len(relevant_set)

# Example
relevant = {"doc1", "doc2", "doc3", "doc4", "doc5"}
retrieved = {"doc1", "doc2", "doc3", "doc6"}

recall = calculate_recall(retrieved, relevant)
print(f"Recall: {recall:.2f}")  # 0.60 (found 3 of 5)
```

**Related Terms:** Precision, F1 Score, Accuracy

**Trade-off:**
- Higher recall = more results, potentially more noise
- Lower recall = fewer results, potentially missing relevant docs
- Balance with precision

---

### Precision

**Definition:** The proportion of retrieved documents that are actually relevant. Higher precision means fewer irrelevant results.

**Example:**
```python
def calculate_precision(retrieved_ids, relevant_ids):
    """Calculate precision@k."""
    retrieved_set = set(retrieved_ids)
    relevant_set = set(relevant_ids)
    
    if not retrieved_set:
        return 0.0
    
    found = len(retrieved_set.intersection(relevant_set))
    return found / len(retrieved_set)

# Example
relevant = {"doc1", "doc2", "doc3"}
retrieved = {"doc1", "doc2", "doc4", "doc5"}

precision = calculate_precision(retrieved, relevant)
print(f"Precision: {precision:.2f}")  # 0.50 (2 of 4 are relevant)
```

**Related Terms:** Recall, F1 Score, Accuracy

**Trade-off:**
- Higher precision = fewer irrelevant results
- Lower precision = more results, potentially more noise
- Balance with recall
