### Question 1

**What is Dialog Engineering?**

- A) Writing code using dialog boxes in a GUI
- B) The discipline of structuring AI conversations as editable, transparent, and deliberately shaped artifacts
- C) Recording conversations between engineers for documentation
- D) Using speech-to-text to write code

<details>
<summary>View Answer</summary>

**Correct Answer: B**

**Explanation:** Dialog Engineering treats the conversation itself as an engineering artifact — something that can be edited, pruned, pinned, and deliberately shaped to maintain clean state and shared understanding across long AI-assisted sessions.

</details>

### Question 2

**What is Polya's framework, as applied to AI-assisted coding?**

- A) Write code, test it, debug it, ship it
- B) Understand the problem, devise a plan, carry out the plan, look back
- C) Ask the AI, accept the output, commit, move on
- D) Gather data, train a model, evaluate, deploy

<details>
<summary>View Answer</summary>

**Correct Answer: B**

**Explanation:** Polya's 1945 framework has four steps: (1) Understand the problem, (2) Devise a plan, (3) Carry out the plan, (4) Look back and review. In AI-assisted coding, the human retains responsibility for steps 1 and 4, while the AI accelerates steps 2 and 3.

</details>

### Question 3

**What problem does Solveit's fluid-dialog design solve that standard chat interfaces have?**

- A) It runs faster on slow internet connections
- B) Context degradation over long sessions — mistakes and off-topic content accumulate and confuse the AI
- C) It supports more programming languages
- D) It automatically deploys the code

<details>
<summary>View Answer</summary>

**Correct Answer: B**

**Explanation:** Standard chat is append-only: every message stays forever, so wrong answers and off-topic detours permanently degrade the AI's context. Solveit lets you hide, delete, or edit messages, so the active context stays clean and focused.

</details>

### Question 4

**What is "understanding debt"?**

- A) The cost of reading documentation
- B) The gap between what code does and what you understand about it
- C) A license fee for using AI assistants
- D) The time it takes to learn a new programming language

<details>
<summary>View Answer</summary>

**Correct Answer: B**

**Explanation:** Every AI-generated line you accept without reading and every library you import without understanding its purpose accrues understanding debt. When the codebase grows beyond what you understand, you reach a "collapse point" where debugging, extending, or shipping becomes impossible.

</details>

### Question 5

**What is a "side quest" in the Solveit methodology?**

- A) A secondary goal unrelated to the main task
- B) A deliberate learning detour to understand an unfamiliar concept suggested by the AI
- C) An extra credit assignment
- D) A background process that runs alongside the main code

<details>
<summary>View Answer</summary>

**Correct Answer: B**

**Explanation:** When the AI suggests something unfamiliar (a library, pattern, or technique), a side quest means pausing to learn about it — ask the AI to explain, write a test, create a flashcard — before returning to the main task.

</details>

### Question 6

**According to Rachel Thomas's "Breaking the Spell of Vibe Coding," what is "dark flow"?**

- A) A state of deep concentration and peak performance
- B) A superficial state that feels productive but is characterized by high-frequency, low-reward iterations
- C) Working late at night without breaks
- D) Using a dark mode code editor

<details>
<summary>View Answer</summary>

**Correct Answer: B**

**Explanation:** "Dark flow" (or "junk flow") adapts Csikszentmihalyi's concept. Unlike true flow (growth-producing and positive), vibe coding induces a superficial addiction similar to "loss disguised as a win" mechanics in slot machines — it *feels* productive without necessarily being so.

</details>

### Question 7

**What is the key difference between vibe coding and Dialog Engineering?**

- A) The programming language used
- B) Vibe coding accepts AI output with minimal review; Dialog Engineering reads every line and verifies each increment
- C) Dialog Engineering is faster
- D) Vibe coding requires more expensive AI models

<details>
<summary>View Answer</summary>

**Correct Answer: B**

**Explanation:** Vibe coding generates large blocks from vague prompts with minimal review, while Dialog Engineering works in small, verified increments where the human reads and understands every line before accepting it.

</details>

### Question 8

**Which two steps of Polya's framework does the lecture identify as the human's core responsibility?**

- A) Step 1 (Understand) and Step 2 (Plan)
- B) Step 1 (Understand) and Step 4 (Review)
- C) Step 2 (Plan) and Step 3 (Execute)
- D) Step 3 (Execute) and Step 4 (Review)

<details>
<summary>View Answer</summary>

**Correct Answer: B**

**Explanation:** The AI can accelerate planning and execution (steps 2 and 3), but understanding the problem and reviewing the solution remain the human's responsibility. Outsourcing either of these is where problems begin.

</details>

### Question 10

**What research finding does Rachel Thomas cite about developers who rely heavily on AI agents?**

- A) They are always more productive
- B) They often *feel* more productive but may actually produce harder-to-maintain code and take longer overall
- C) They write fewer bugs
- D) They have higher job satisfaction

<details>
<summary>View Answer</summary>

**Correct Answer: B**

**Explanation:** Citing METR research, Thomas notes that developers using heavy AI assistance often report feeling significantly more productive even when objective measures show slower progress and less maintainable code. This perception gap is part of the "dark flow" phenomenon.

</details>
